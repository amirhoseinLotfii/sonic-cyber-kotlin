# 🔬 گزارش عمیق پایگاه دانش فنی: توسعه بازی سونیک سایبر برای اندروید با کاتلین (Kotlin Native)

این سند مرجع تخصصی معماری، فیزیک ریاضیاتی، ساختار حافظه و موتور بازی‌سازی برای پیاده‌سازی پروژه **Sonic Cyber Overdrive** با زبان **Kotlin** برای سیستم‌عامل **Android** است.

برای توسعه بازی ۲.۵ بعدی / رانر سرعتی با کاتلین در اندروید، سه رویکرد اصلی ارزیابی شد:

### ۱. مقایسه تخصصی فریم‌ورک‌ها:
| شاخص | LibGDX (با Kotlin) | Google Filament / Sceneview | Native SurfaceView / OpenGL ES 3.0 |

### نتیجه‌گیری و انتخاب نهایی معماری:
برای دستیابی به فیزیک دقیق ۱۰۰٪ منطبق بر بازی‌های اصلی سونیک (Sonic Retro Physics)، معماری **Native Android Game Engine با کاتلین** بر پایه **Custom SurfaceView + Dedicated GameThread + Fixed Timestep Loop** یا **LibGDX با پسوند کاتلین** انتخاب می‌شود. برای پیاده‌سازی سبک، پایدار، بدون لگ و قابل اجرا روی تمام پردازنده‌های گرافیکی اندروید (Snapdragon Adreno، MediaTek Mali و PowerVR)، یک **موتور بازی بومی کاتلین (Pure Kotlin Android Engine)** با حداقل وابستگی خارجی و حداکثر بهره‌وری رندرینگ طراحی می‌گردد.

## 🗂️ کارت ۲: فیزیک ریاضیاتی مومنتوم سونیک (Sonic the Hedgehog Physics Guide)

فیزیک سونیک با بازی‌های پلتفرمر عادی متفاوت است. این فیزیک بر پایه **سرعت زمینی ($G_{spd}$)** و **حالت‌های ۴ گانه چرخش ۳۶۰ درجه** کار می‌کند.

### ۱. متغیرها و محاسبات ساب‌پیکسل (Subpixel Arithmetic):
در بازی‌های کلاسیک سگا، موقعیت بر مبنای ساب‌پیکسل محاسبه می‌شود ($1 \text{ pixel} = 256 \text{ subpixels}$):
- **$G_{spd}$ (Ground Speed):** اسکالر سرعت در امتداد زاویه مماس زمین.
- **شتاب (Acceleration):** $0.046875 \text{ px/frame}$ ($12 \text{ subpixels}$).
- **کاهش سرعت / ترمز (Deceleration):** $0.5 \text{ px/frame}$ ($128 \text{ subpixels}$).
- **اصطکاک (Friction):** $0.046875 \text{ px/frame}$.
- **حداکثر سرعت استاندارد ($Top_{spd}$):** $6.0 \text{ px/frame}$ ($1536 \text{ subpixels}$).
- **گرانش ($Gravity$):** $0.21875 \text{ px/frame}$.

### ۲. معادله نیروی شیب (Slope Force Equation):
هنگام حرکت روی سطوح زاویه‌دار، گرانش مستقیماً روی سرعت مماس تاثیر می‌گذارد:
$$\text{SlopeForce} = -G \cdot \sin(\theta)$$
$$G_{spd(t+1)} = G_{spd(t)} + \text{SlopeForce}$$

- **سربالایی ($\theta > 0$):** مقدار $\sin(\theta)$ مثبت بوده و سرعت کاهش می‌یابد.
- **سرازیر ($\theta < 0$):** سرعت به‌صورت نمایی افزایش می‌یابد.

### ۳. حد لغزش و سقوط از دیواره (Slip Threshold):
اگر سونیک روی شیب‌های تند ($\theta > 45^\circ$) باشد و سرعت او از آستانه بحرانی کمتر شود:
$$\text{If } |G_{spd}| < 2.5 \text{ px/frame and } \theta \in [46^\circ, 314^\circ] \implies \text{Detach and Fall}$$

### ۴. سیستم ۴ ربعی چرخش ۳۶۰ درجه و لوپ‌ها (4-Quadrant Collision Modes):
برای اینکه سونیک بتواند روی دیوارها و سقف لوپ بدود، حالت برخورد براساس زاویه چرخش تغییر می‌کند:
1. **Floor Mode ($315^\circ \text{ تا } 45^\circ$):** گرانش به سمت پایین. سنسورهای A و B فعال هستند.
2. **Right Wall Mode ($46^\circ \text{ تا } 134^\circ$):** گرانش به سمت چپ متمایل است. سنسورها ۹۰ درجه می‌چرخند.
3. **Ceiling Mode ($135^\circ \text{ تا } 225^\circ$):** گرانش به سمت بالا. سنسورهای C و D برای راه رفتن روی سقف فعال می‌شوند.
4. **Left Wall Mode ($226^\circ \text{ تا } 314^\circ$):** گرانش به سمت راست متمایل است.

### ۵. فیزیک عبور از لوپ (Loop Traversal Physics):
برای عبور از بالاترین نقطه لوپ (Apex) بدون سقوط، سرعت زاویه‌ای باید بر شتاب گرانش غلبه کند:
$$G_{spd\_min} \ge \sqrt{r \cdot g}$$
اگر سرعت کمتر از این مقدار باشد، کاراکتر از سقف جدا شده و سقوط آزاد می‌کند.

### ۶. مکانیک اسپین‌دش (Spin Dash Charge):
- با نگه داشتن جهت پایین و زدن مکرر پرش، متغیر `revCharge` از 0 تا 8 افزایش می‌یابد.
- در لحظه رهاسازی دکمه پایین:
  $$G_{spd} = 8.0 + (\text{revCharge} \times 1.5)$$
  همراه با تغییر حالت کاراکتر به `ROLLING` و کاهش ابعاد هیت‌باکس.

## 🗂️ کارت ۳: معماری مپ، چانک‌ها و استریم مرحله (Sonic Chunk & Map Architecture)

در موتورهای سونیک، مپ به صورت یک ساختار سلسله‌مراتبی داده‌ای ذخیره می‌شود تا مصرف رم به حداقل برسد:

```
[Level Grid Layout]  -->  شبکه دوبعدی از ایندکس چانک‌ها
        │
        ▼
[128×128 Chunks]     -->  هر چانک شامل ۶۴ بلوک (۸×۸)
        │
        ▼
[16×16 Blocks]       -->  دارای ارتفاع سنسور (Height Array) و زاویه سطح (Angle Byte 0..255)
        │
        ▼
[8×8 Base Tiles]     -->  پیکسل‌های گرافیکی خام در بافر GPU
```

### استریمینگ نامحدود (Endless Procedural Chunk Streaming):
در سبک Endless Runner:
1. چانک‌ها در یک بافر حلقوی (`CircularBuffer<SonicChunk>`) نگهداری می‌شوند.
2. با عبور بازیکن از چانک جاری، چانک‌های پشت سر از رم بازیافت شده (Object Pooling) و چانک‌های بعدی براساس الگوهای تصادفی هوشمند (شیب، ریل، لوپ و پرتگاه) تولید می‌شوند.
3. زباله‌روب اندروید (Garbage Collector) در حین بازی فعال نمی‌شود، زیرا هیچ شیء جدیدی `new` نمی‌شود.

## 🗂️ کارت ۴: ماشین وضعیت کاراکتر سونیک (Sonic Finite State Machine - FSM)

کاراکتر در هر لحظه در یکی از وضعیت‌های انحصاری زیر قرار دارد:
- `IDLE`: توقف کامل، اجرای انیمیشن نگاه به ساعت یا حرکات درجا.
- `LOOKING_UP`: نگاه به بالا برای جابجایی دوربین.
- `CROUCHING`: خم شدن روی زمین (آمادگی برای اسپین‌دش).
- `SPINDASH_CHARGING`: چرخش سریع درجا و شارژ دور موتور.
- `WALKING / RUNNING / PEELOUT`: حرکت روی زمین بر اساس میزان $G_{spd}$.
- `ROLLING`: غلتیدن با هیت‌باکس کوچک (آسیب‌ناپذیر به موانع زمینی).
- `JUMPING`: پرش هوایی با حالت توپی و دکمه‌زنی پویا (Jump Cut-off).
- `LOOP_TRAVERSAL`: قفل مسیر روی لوپ‌های سه‌بعدی و ریلی.
- `HURT / RING_SCATTER`: آسیب دیدن، پرتاب به عقب و پخش حلقه‌ها روی زمین.

## 🗂️ کارت ۵: مدیریت چرخه حیات اندروید، هوک‌ها و لوپ تردینگ (Android Lifecycle & Hooks)

### ۱. حلقه بازی با گام زمانی ثابت (Fixed Timestep Accumulator Loop):
برای اجرای نرم روی نمایشگرهای ۶۰، ۹۰ و ۱۲۰ هرتز اندروید بدون وابسته بودن فیزیک به نرخ فریم:
```kotlin
val DT = 1.0f / 60.0f // گام ثابت ۶۰ فریم
var accumulator = 0.0f
var currentTime = System.nanoTime()

while (running) {
    val newTime = System.nanoTime()
    var frameTime = (newTime - currentTime) / 1_000_000_000.0f
    currentTime = newTime
    if (frameTime > 0.25f) frameTime = 0.25f // جلوگیری از spiral of death

    accumulator += frameTime
    while (accumulator >= DT) {
        physics.step(DT)
        accumulator -= DT
    }
    val alpha = accumulator / DT
    render(alpha) // درون‌یابی نرم بین دو فریم
}
```

### ۲. اتصال به چرخه حیات اکتیویتی (Lifecycle Hooks):
- `onPause`: توقف فوری `GameThread`، ذخیره امتیاز و حلقه‌ها در `DataStore`، متوقف کردن صوت برای جلوگیری از نشت صدا در پس‌زمینه.
- `onResume`: بازیابی منابع گرافیکی، راه‌اندازی مجدد `SurfaceHolder.Callback` و از سرگیری لوپ.
- `onWindowFocusChanged`: مدیریت بازیابی پس از مینیمایز یا باز شدن نوتیفیکیشن اندروید.
